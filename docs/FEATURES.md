# 核特徴量の定義と読み方

`tools/hovernet/extract_nuclear_features.py` の出力を説明します。特徴量は **HoVer-Net が推定した核輪郭に対する計測値**です。輪郭が間違っていれば特徴量も影響を受けます。測定値や型ラベルだけで良悪性や患者リスクを判定するものではありません。

## 1. どの単位で測るか

入力は1枚の画像パッチに対応する `.db` です。CSV の1行は、そのパッチ内の1つの核オブジェクトです。

```text
核輪郭の座標（px）
        × パッチの MPP（µm/px）
        ↓
長さ（µm）と面積（µm²）
```

長さは `px × MPP`、面積は `px² × MPP²` で換算します。MPP はパッチのものを使用し、元 WSI の MPP と取り違えないでください。正しい単位へ換算することと、異なるスキャナ・染色・倍率間で同等の精度が得られることは別問題です。

## 2. `nuclear_features.csv` の列

| 列名 | 定義・読み方 |
|---|---|
| `nucleus_id` | AnnotationStore 内の核オブジェクト ID。患者 ID ではない |
| `nucleus_type` | 入力の `type` プロパティを文字列にしたモデル由来の型ラベル。欠落時は `Unclassified` |
| `probability` | 入力の `prob` プロパティがあればその値。ない場合は欠損。臨床的な癌確率ではない |
| `geometry_type` | 計測に用いた幾何形状。通常は `Polygon` |
| `geometry_is_valid` | 幾何演算ライブラリによる形状の妥当性。現行コードは無効な形状を除外するため出力では真。病理学的に正しい核かどうかの判定ではない |
| `touches_patch_edge` | 外輪郭が画像境界に接するか。切断された可能性のある核を確認するためのフラグ |
| `centroid_x_um`, `centroid_y_um` | パッチ内の核中心座標を µm に換算した値。WSI 全体の絶対座標ではない |
| `area_um2` | 核ポリゴンの面積（µm²） |
| `perimeter_um` | 核ポリゴンの周囲長（µm）。内孔がある形状ではその境界長も含む |
| `long_axis_um` | 外輪郭へ当てはめた楕円の長軸の全長（µm）。半径ではない |
| `short_axis_um` | 同じ楕円の短軸の全長（µm）。半径ではない |
| `orientation_deg` | 楕円の長軸方向（度）。`0 ≤ angle < 180` の軸方向データ |
| `ellipse_fit_status` | 楕円近似が得られれば `ok`、得られなければ `not_available` |
| `circularity` | 円形度。`4π × 面積 / 周囲長²`。無次元 |
| `solidity` | `核面積 / 核の凸包面積`。無次元 |
| `mpp_um_per_px` | この計測に使ったパッチの MPP（µm/px） |
| `source_db`, `source_patch` | 入力ファイルのパス。ローカル絶対パスを含むため、公開時には注意 |

実際の列名は `long_axis_um` と `short_axis_um` です。`major_axis_um`／`minor_axis_um` という別名の列は出力しません。

### 面積・長径・短径

面積と周囲長は輪郭ポリゴンから計算します。長径・短径は OpenCV の `fitEllipse` による楕円近似です。最大の2点間距離（Feret 径）や画像領域の二次モーメントによる軸長と同じ定義ではありません。

外輪郭の点が5点未満、楕円近似の失敗、軸長が正でない場合は、長径・短径・方向を欠損値にします。CSV の空欄を0へ置換しないでください。面積など他の測定が得られることはあります。

### 円形度（circularity）

```text
circularity = 4πA / P²
A：核面積、P：核周囲長
```

理想的な円は1です。同じ面積でも細長い形や周囲が複雑な形では低くなる傾向があります。輪郭の解像度、ギザギザ、セグメンテーション誤差にも影響されるため、低値をただちに核異型と解釈できません。実装では値を0〜1へ強制的に切り詰めていません。

### Solidity

凸包とは、核の外周全体を包む最小の凸形状です。輪郭のくぼみを埋めた形と考えると理解しやすくなります。

```text
solidity = 核面積 / 凸包面積
```

有効なポリゴンであれば通常は0より大きく1以下です。くぼみや欠損の少ない凸な形は1に近くなります。ただし細長い楕円も凸なので1に近く、solidity は「丸さ」そのものではありません。

### 長軸方向（orientation）：単純平均しない

画像座標は x が右向き、y が下向きです。方向は画像に対するものであり、人体の解剖学的な方向を示しません。0°と180°は同じ軸です。そのため1°と179°の単純平均90°は適切な代表方向ではありません。

集約する場合は角度を2倍して円周統計を計算し、最後に半分に戻すなど、**軸方向データとしての統計**が必要です。ほぼ円形の核では長軸方向自体が不安定になります。現行のサマリー CSV は方向の平均・中央値を計算しません。

## 3. 核の採用と品質確認

計測では Polygon を使います。MultiPolygon は最大面積の成分1つを選ぶため、元のすべての成分を合計するものではありません。空の形状、対応外の形状、外輪郭点が3点未満、幾何学的に無効なポリゴン、座標が有限でないもの、面積・周囲長・凸包面積が有限の正数でないものはスキップします。

`touches_patch_edge` は x または y の最小値が0以下、または最大値が `画像サイズ - 1` 以上の場合に真となります。切断核の可能性を知らせる目安であり、切断を完全に検出する判定ではありません。

既定では **境界に接する核を除外せず、フラグを付けて集約**します。`--exclude-edge` を付けた場合は、該当核を核単位 CSV、サマリー、型別核数、重ね合わせ画像から除外します。採用方針は `edge_policy` に `retain_and_flag` または `exclude` として記録され、除外数は `n_excluded_edge` に記録されます。

研究用の解析ではフラグと輪郭を確認し、どの核を採用するかを事前に定義してください。後処理でさらに除外した場合は、除外後の核からサマリーを再計算する必要があります。`n_skipped_invalid_geometry` は計測不可能な形状等のスキップ件数であり、境界核として除外した件数とは別です。除外後に核が残らなければスクリプトはエラーで停止し、ゼロ行を成功結果として出力しません。

## 4. `nuclear_feature_summary.csv` の集約

このパッチで CSV に残った核を、型ラベルで選別せずまとめます。1行は **1パッチの要約**であり、1症例の全腫瘍を代表する値ではありません。

対象特徴量は `area_um2`、`long_axis_um`、`short_axis_um`、`circularity`、`solidity` の5種類です。それぞれに以下の接尾辞を付けます。例：`area_um2_median`。

| 接尾辞 | 統計量 |
|---|---|
| `_mean` | 算術平均 |
| `_sd` | 標本標準偏差（分母は n−1）。有効値が1件なら欠損 |
| `_median` | 中央値 |
| `_q05`, `_q25`, `_q75`, `_q95` | 5、25、75、95 パーセンタイル（NumPy の既定の分位点計算） |
| `_iqr` | 四分位範囲：q75−q25 |

特徴量ごとに欠損値を除いて計算します。そのため、楕円近似が得られない核がある場合は、面積と長径で集約対象数が異なることがあります。有効値が0件なら統計量は欠損です。

サマリーには `annotation_store`、`patch`、`mpp_um_per_px`、`n_nuclei`、`n_skipped_invalid_geometry`、`n_excluded_edge`、`edge_policy` も含みます。`n_nuclei` は採用後の核数です。周囲長、中心座標、方向、モデル確率はこのサマリーの対象ではありません。

平均か中央値のどちらかが常に正しいわけではありません。分布や外れ値を確認し、研究目的と事前計画に合わせて選びます。このコードは記述統計を並べて出力するだけで、特徴量の選択、LASSO、Cox 回帰、high／low 分類は行いません。

## 5. 型別核数と色の対応

`nucleus_type_counts.csv` は、出力された核の `nucleus_type` ごとの件数です。`nuclei_overlay.png` では次の完全一致するラベル名に色を割り当てています。

| ラベル | 表示上の意味 | RGB |
|---|---|---|
| `Neoplastic` | 腫瘍性と推定された型 | 230, 76, 60（赤） |
| `Inflammatory` | 炎症細胞と推定された型 | 48, 105, 210（青） |
| `Connective` | 結合組織系と推定された型 | 65, 168, 90（緑） |
| `Dead` | 死細胞に対応する型 | 245, 166, 35（橙） |
| `Non-Neoplastic Epithelial` | 非腫瘍性上皮と推定された型 | 152, 78, 163（紫） |
| `Background` | 背景ラベル | 120, 120, 120（灰） |
| 上記以外 | 未分類または想定外のラベル | 230, 170, 0（黄褐色） |

PanNuke 由来の型ラベルは膀胱癌専用の正解アノテーションではありません。`Neoplastic` の核だけを集めても、病理医が確認した腫瘍 ROI の代わりにはなりません。ラベル文字列が異なれば既定色になるため、色だけでなく CSV のラベルと `feature_metadata.json` を確認してください。

## 6. 症例単位の解析へ進む前に

腫瘍 ROI の確認、核検出・輪郭・型分類の検証、尺度の統一、パッチ境界の扱い、重複核の除去、症例内の領域選択、欠損値処理、集約方法を決めます。パッチ平均をさらに単純平均すると核数の異なるパッチを同じ重みで扱うため、核を直接まとめた平均と一致しない場合があります。症例特徴量を作る場合は集約単位と重み付けも記録してください。
